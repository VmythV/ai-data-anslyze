# 使用指南

## 一、管理员：首次配置

打开系统，输入访问口令，进入左下角「设置」。

### 1. 模型渠道
添加一个模型渠道：协议、Base URL、API Key、模型名，点「测试」确认连通。可以添加多个，设一个为默认。

- **Anthropic 兼容**：Base URL 不含 `/v1/messages`，如 `https://api.anthropic.com`。
- **OpenAI 兼容**：Base URL 含 `/v1`，如 `https://api.openai.com/v1`；渠道必须支持 Responses API（`/v1/responses`），只有 Chat Completions 的网关不能用。

> 对话中途切换渠道，AI 会从头开始（页面上的历史消息仍保留）。

### 2. 数据源
点「添加」，选择类型（MySQL / PostgreSQL / ClickHouse / MongoDB），填写：

| 字段 | 说明 |
|---|---|
| 名称 | 给人看的名字，如「会员营销库」 |
| 标识 | 英文短名，如 `crm`。AI 用它指代这个数据源；填库名时会自动带出 |
| 主机 / 端口 / 用户名 / 密码 / 数据库 | 连接信息。**强烈建议用只读账号** |
| 类型专属选项 | PG 的 SSL 模式、ClickHouse 是否 HTTPS、MongoDB 的认证库 / 副本集 / TLS |
| 业务说明 | 写给 AI 看的：指标口径、表之间的关系、注意事项。**写得越清楚，分析越准** |

先点「测试连接」，通过后保存。保存后平台会在后台读取表结构缓存；表结构有变化时点「刷新表结构」。

业务说明示例：

```
- GMV 统计 orders.pay_amount，只算「已完成」和「配送中」
- 大区信息在 regions 表，通过 region_id 关联
- 金额单位是元
```

### 3. 数据域（可选）
把业务上相关的数据源编成一组（如「电商经营」= 订单库 + 仓储库 + 会员库），对话时整组选择。数据域的说明会写进 AI 的系统提示，适合写跨库的统一口径，例如「客户维度以订单库的客户 ID 为准」。

### 4. 关联关系（多数据源时建议配置）
告诉 AI 不同库之间靠哪些字段关联：

- **手动添加**：选两端的「数据源 → 表 → 字段」，再选对应关系（多对一、一对一……），取值格式不同时写上转换规则（如「会员号去掉前缀 M 后等于客户 ID」）
- **推断关联**：点「推断关联」，平台根据字段注释、同名字段、命名约定找候选，再抽样核对取值匹配率，达标的放进「待审核」。逐条看过后点「采纳」
- **AI 在对话中提交的**：也会出现在「待审核」里，标「AI 推断」和匹配率

只有「已确认」的关联会告诉所有会话的 AI。

### 5. 联邦查询（可选）
「数据源」页顶部显示联邦查询状态。启用后，AI 可以用一条 SQL 跨不同类型的数据库关联明细数据。启用方法见 [部署与运维](operations.md)。

## 二、用户：提问

### 1. 开始一次分析
1. 左上角「新建分析」
2. 输入框上方选择数据源：选一个**数据域**，或在「数据源」页签里勾选几个数据源（会记住上次的选择）
3. 选择模型（默认即可）
4. 输入问题，回车发送

### 2. 怎么问效果好

| 建议 | 例子 |
|---|---|
| 说清指标、维度、时间范围 | 「2025 年各大区的销售额，按月看趋势」 |
| 问「为什么」时给出现象 | 「10 月退款率比 9 月高，原因是什么？」 |
| 需要沉淀时直接说 | 「帮我出一份上季度的经营分析报告」 |
| 跨库问题直接问业务 | 「送货慢会不会影响客户满意度？」——AI 自己判断要用哪几个库、怎么关联 |
| 连续追问 | 「按渠道拆开看看」「只看华东」 |

问题比较含糊时，AI 会在输入框上方弹出选择题请你确认口径：点选即可（单选点一下会跳到下一题），没有合适选项就选「其他」自己填写；也可以关掉面板直接打字回答。

### 3. 读懂回答

一次完整的回答通常是：

1. **指标卡**：关键数字，▲ 绿色表示向好，▼ 红色表示变差（注意：退款率上升是红色）
2. **图表**：1~3 张，标题就是结论；多张时两列排布；右上角可以下载图片
3. **几条要点**：结论、口径、需要注意的数据问题、建议

其余内容默认折叠，需要时展开：

| 内容 | 怎么看 |
|---|---|
| 分析步骤 | 点「N 个分析步骤」，再点某一步看 SQL / 脚本和输出 |
| 查询结果 | 表格卡片标了数据源，点开看前 200 行；右侧 `</>` 看查询语句。标「联邦」的是联邦查询的结果 |
| 报告 | 报告卡片「预览」或下载 HTML（单文件，可以离线打开、打印） |
| 用量 | 回答底部一行：用时、调用模型次数、token；鼠标悬停看缓存命中和估算费用 |

### 4. 其他操作
- **停止**：分析过程中，发送按钮变成停止按钮
- **切换数据源 / 模型**：对话中途也可以改；改模型会开始新的上下文（历史消息仍在页面上）
- **删除会话**：左侧会话列表悬停时出现删除按钮，会同时清掉它的查询结果、报告文件

## 三、常见问题

**AI 说找不到某张表？**
确认这张表所在的数据源被选中；在「设置 → 数据源」刷新表结构。

**数字和我们的报表对不上？**
多半是口径不同。展开分析步骤看 SQL 用的过滤条件；把正确口径写进数据源的「业务说明」，以后的对话都会遵循。

**跨库结果里说「匹配率不高」？**
说明两个库的关联字段有一部分对不上（比如部分客户没注册会员）。这是数据本身的情况，AI 会如实说明。如果是关联字段选错了，在「关联关系」里配置正确的关联。

**回答太慢？**
跨引擎的联邦查询、大表查询会慢一些；可以把时间范围缩小。超出并发上限时会显示「正在排队」。
