# 系统介绍

## 一句话

**AI 数据分析**是一个部署在内网的对话式数据分析平台：业务人员用自然语言提问，AI 自己去找表、写只读查询、做计算、画图，把结论以指标卡 + 图表 + 几条要点的形式给出，并能沉淀成一份可以离线打开的 HTML 报告。

## 解决什么问题

| 以前 | 现在 |
|---|---|
| 提需求给数据同学，排期、写 SQL、做图表，往返几天 | 直接在对话里问，几十秒到几分钟拿到带图的结论 |
| 数据分散在 MySQL、PostgreSQL、ClickHouse、MongoDB 等多个库里，跨库关联要导数据 | 一次对话可以同时用多个数据源，跨库关联由 AI 选择合适的方式完成 |
| 结论是一大段文字或一张 Excel | 以图为主：指标卡、图表两列排布，文字只留要点 |
| 问题问得含糊，得来回沟通口径 | AI 发现口径有歧义时，在输入框上方给出单选 / 多选题让你点选 |

## 核心能力

### 1. 对话式分析
- 自然语言提问，支持连续追问（会话保留上下文）
- 过程透明：每一步查了什么、写了什么 SQL / 脚本都能展开查看
- 流式输出，刷新页面、断网重连后接着看；可以随时停止
- 每条回答显示用时、调用模型次数和 token 用量

### 2. 多数据源
- 支持 **MySQL、PostgreSQL、ClickHouse、MongoDB**
- 一次对话可以手动勾选多个数据源，或选择管理员编好的**数据域**（一组相关的数据源）
- 三种跨库关联方式，AI 按情况选择：
  - **A. 同连接直接 JOIN**：同一实例上的库，一条 SQL 搞定
  - **B. 结果级关联**：各自查询、汇总后在 Python 沙箱里用 DuckDB 关联
  - **C. 联邦查询**（可选，Trino）：一条 SQL 跨任意引擎关联明细数据
- 数据源多了也能找准：**表结构缓存 + 关键词搜索**

### 3. 关联关系的三种来源（互相补充）
- **结构化配置**：管理员在设置页逐条配置「哪个库的哪个字段对应哪个库的哪个字段」
- **自由文本**：数据源、数据域的业务说明
- **AI 推断**：设置页一键推断（根据字段注释、同名字段、命名约定找候选，再抽样核对取值匹配率）；AI 在对话中发现的关联也会提交。AI 推断的一律进入「待审核」，管理员采纳后才对所有会话生效

### 4. 可视化输出
- **指标卡**：关键数字大号展示，带涨跌箭头和好坏颜色
- **图表**：ECharts，统一主题与配色（经色觉障碍校验），亮 / 暗色自适应，可下载图片
- **HTML 报告**：固定版式（核心结论、指标卡、图表、解读、表格），单文件、离线可看、可打印

### 5. 引导式提问
意图不明确时，AI 用单选 / 多选题向你确认（每题都可以选「其他」自己填写），这一轮随即结束；你的选择作为下一条消息发回，AI 按选择继续分析。

### 6. 安全
- AI 只能执行只读查询（语句校验 + 数据库会话只读 + 建议只读账号，三层）
- AI 写的 Python 在隔离的沙箱容器里运行：不能联网、碰不到业务库和平台数据，并发任务之间互相隔离
- 数据源密码、模型 API Key 加密保存；全站访问口令

## AI 能做什么（工具与技能）

AI 由 Claude Agent SDK（Anthropic 协议渠道）或 Codex SDK（OpenAI 协议渠道）驱动，平台给它的能力分两类：

**工具**（AI 可以调用的动作）

| 工具 | 作用 |
|---|---|
| `search_schema` | 按关键词在已选数据源里找相关的表和字段 |
| `list_tables` / `describe_table` | 看有哪些表、字段含义、常见取值、样例数据 |
| `run_sql` | 在 MySQL / PostgreSQL / ClickHouse 上执行只读 SQL |
| `run_mongo` | 在 MongoDB 上执行只读聚合管道 |
| `run_federated_sql` | 联邦查询：一条 SQL 跨数据源（启用 Trino 时） |
| `run_python` | 在沙箱里用 pandas / DuckDB 等做进一步计算 |
| `render_kpis` / `render_chart` | 展示指标卡 / 图表 |
| `publish_report` | 生成 HTML 报告 |
| `ask_user` | 以单选 / 多选题向用户确认意图 |
| `propose_relation` | 把发现的跨源关联提交给管理员审核 |

**技能（Skill）**：写在 `backend/src/data_analyze/plugin/skills/*/SKILL.md` 里的分析方法论，AI 按需加载。改这些文件就能调整 AI 的分析习惯，不用改代码。

| 技能 | 内容 |
|---|---|
| data-exploration | 理解意图、确认口径、摸清表结构、回答的样子 |
| sql-analysis | 时间分桶、同比环比、占比排名等写法，三种 SQL 方言差异 |
| mongo-query | 聚合管道写法、日期与嵌套字段 |
| cross-source | 选择跨源关联方式、核对匹配率、提交新发现的关联 |
| python-analysis | 沙箱约束、pandas / DuckDB 套路 |
| chart-design | 选图规则、ECharts 写法范例、可视化优先的回答规范 |
| report-writing | 报告结构、结论写法 |

## 术语

| 术语 | 含义 |
|---|---|
| 数据源 | 一个可查询的数据库连接（类型 + 主机 + 账号 + 库名） |
| 标识（alias） | 数据源的英文短名，如 `shop`、`crm`。AI 调用工具、写联邦 SQL 时用它指代数据源 |
| 数据域 | 管理员编好的一组相关数据源，对话时可以整组选择 |
| 同一连接 | 主机、端口、账号都相同的数据源，可以在一条 SQL 里互相引用 |
| 关联关系 | 两个表字段之间的对应关系（如 `shop.orders.order_no ↔ wms.shipments.order_no`） |
| 匹配率 | 从一侧抽样的取值，有多少能在另一侧找到；用来判断关联是否可靠 |
| 工作区 | 每个会话独立的目录，存放查询结果文件（parquet）、Python 脚本及其产出 |
| 产物 | 图表与 HTML 报告 |
| 联邦查询 | 由 Trino 把多个数据库映射成一个查询入口，一条 SQL 跨引擎关联 |
