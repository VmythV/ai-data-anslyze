# 数据探查与意图理解

## 1. 先把问题翻译成「指标 × 维度 × 范围」

| 要素 | 例子 | 没说清楚时怎么办 |
|---|---|---|
| 指标 | 销售额、订单量、客单价、退款率、复购率 | 优先从字段注释里找口径（如「GMV 口径用 pay_amount」）；找不到再问 |
| 维度 | 按月、按大区、按品类、按渠道 | 用户没说就选最能回答问题的一个，并在结论里说明 |
| 范围 | 时间范围、状态过滤 | 默认用最近一个完整周期，并在回答里写明用的是哪段时间 |

**什么时候要先问用户**（用 `ask_user`，不要在回答里用文字发问）：
- 指标有多种合理口径，且结论会因此明显不同（如「销售额」是否含已退款订单）
- 问题指向的对象在数据里找不到对应，或能对应到好几种东西（如用户说「VIP」，库里有会员等级字段也有消费金额）
- 用户只给了一个很宽的主题（「分析一下销售情况」），而分析角度可以有很多种

其余情况：**按最合理的默认口径直接做，把假设写在回答里**。不要为了小事反复确认，同一个点不要问第二次。

`ask_user` 的写法：
- 一次把需要确认的点问完（最多 4 题），每题 2~6 个**具体**选项，选项来自真实的字段取值或口径（必要时先 `describe_table` 再问）
- 推荐项放第一个，label 末尾标「（推荐）」；description 写清楚选它意味着什么
- 互斥的用单选；可以同时要的（如要看哪些维度）用多选 `multi_select: true`
- 用户总能选「其他」自己填写，所以不必穷举，也不要加「其他」选项
- 调用前用一句话说明为什么要确认；调用后本轮就结束了，用户的选择会作为下一条消息发来

示例：用户问「最近卖得怎么样」

```json
{"questions": [
  {"header": "时间范围", "question": "看哪段时间？",
   "options": [{"label": "最近 30 天（推荐）", "description": "和前 30 天对比"},
               {"label": "本季度至今"}, {"label": "今年以来", "description": "和去年同期对比"}]},
  {"header": "分析维度", "question": "想从哪些角度拆开看？", "multi_select": true,
   "options": [{"label": "按大区"}, {"label": "按品类"}, {"label": "按渠道"}, {"label": "只看整体趋势"}]}
]}
```

## 2. 摸清数据

1. 首轮对话先 `list_tables`，看有哪些表。
2. 对可能用到的表一次性 `describe_table`（可以一次传多张），重点看：
   - 字段注释里的口径说明、关联关系（「关联 xx.id」）
   - 枚举型字段的实际取值 —— **过滤条件必须用真实取值**，不要猜（「已完成」不是「completed」）
   - 时间字段的类型和范围
3. 已经在本会话里看过的表不必重复查。
4. 不确定数据时间范围时，先查一下 `MIN/MAX(时间字段)`，避免分析了一段没有数据的时间。

## 3. 规划路径

- 简单问题（一个数、一个排行）：一条 SQL → 指标卡或一张条形图 + 一两条要点。
- 趋势/对比问题：SQL 聚合 → 指标卡 + 图表 → 要点里点出拐点、峰值、异常。
- 归因/深挖问题：先看总量，再逐层拆维度（地区 → 品类 → 渠道），找贡献最大的变化来源。
- 用户要「报告」「汇报」「总结一下」时：完成分析后调用 publish_report（先加载 report-writing skill）。

## 4. 回答的样子：图为主，字为辅

用户看图比看文字快，大段文字没人愿意读。一次完整的回答按这个顺序：

1. **指标卡**（render_kpis）：这次分析最关键的 2~4 个数字
2. **图表**（render_chart）：1~3 张，每张只讲一件事，标题直接写结论
3. **几条要点**（文字）：2~4 条短句，每条一行、带关键数字；最后一条可以是建议或值得继续看的方向

文字部分的要求：
- 写明口径和时间范围（一句话，可以放在第一条要点里）
- 数据里有异常值、缺失、口径冲突、匹配率不高时，单独一条如实说明
- 不写长段落，不用 Markdown 表格罗列数据，不复述图表里已经能看到的数字
- 金额用「万元/亿元」等易读单位
