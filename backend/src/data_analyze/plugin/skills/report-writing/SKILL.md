# 撰写分析报告（publish_report）

报告版式由平台固定（简约卡片风格，自动适配亮/暗色、可打印），你负责内容。

## 结构（自上而下）

1. **title**：说清主题和范围，如「2025 年销售复盘」「Q3 退款率异常分析」。
2. **subtitle**：数据范围与口径，如「2024-01 至 2026-10 · GMV 按实付金额 · 不含已取消订单」。
3. **summary（核心结论）**：3~5 条 Markdown 列表。每条 = 判断 + 关键数字，最重要的放第一条。
   - 好：「**华东贡献 38% 的 GMV**，同比增长 27%，是增长的主要来源」
   - 差：「华东地区表现较好」
4. **sections**，一般顺序：
   - `kpis`：3~4 个核心指标卡，`delta` 写变化（如「同比 +25.3%」），`tone` 用 good / bad / neutral 表示好坏（**增长不一定是好**，如退款率上升是 bad）
   - `chart`：引用本会话里 render_chart 返回的 chart_id，`caption` 用一句话写出该图的结论
   - `markdown`：对图表的解读、原因分析、建议
   - `table`：需要明细时附上（引用 data_file，max_rows 控制在 20 以内）
   - 最后一个 `markdown` 段落写「建议与下一步」，以及口径说明和数据局限

## 规则

- 报告里出现的每个数字都必须来自本次查询结果，不能编造或估算后当成事实。
- 报告用的图要先用 render_chart 画出来（用户会在对话里先看到），再在报告里引用。
- 篇幅：3~6 个图表/表格段落为宜，宁缺毋滥。
- 金额统一单位（万元或亿元），百分比保留 1 位小数。
- 生成后在对话里用一两句话告诉用户报告的要点，不要把整份报告再复述一遍。

## 调用示例

```json
{
  "title": "2025 年销售复盘",
  "subtitle": "2025-01-01 至 2025-12-31 · GMV 按实付金额 · 不含已取消、已退款订单",
  "summary": "- **全年 GMV 3,120 万元，同比 +24.8%**，增速较 2024 年提升 3 个百分点\n- 11 月（双 11）单月贡献 15%，是全年峰值\n- 小程序渠道订单占比从 15% 升至 31%，是增长最快的渠道",
  "sections": [
    {"type": "kpis", "items": [
      {"label": "GMV", "value": "3,120 万元", "delta": "同比 +24.8%", "tone": "good"},
      {"label": "订单数", "value": "18.2 万", "delta": "同比 +21.5%", "tone": "good"},
      {"label": "客单价", "value": "171 元", "delta": "同比 +2.7%", "tone": "good"},
      {"label": "退款率", "value": "6.1%", "delta": "同比 +0.4pt", "tone": "bad"}
    ]},
    {"type": "chart", "chart_id": "<render_chart 返回的 id>", "caption": "6 月、11 月大促明显拉高全年曲线"},
    {"type": "markdown", "title": "解读", "content": "..."},
    {"type": "markdown", "title": "建议与下一步", "content": "1. ...\n2. ..."}
  ]
}
```
